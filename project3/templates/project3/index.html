Active learning for learning to defer

A classifier and a simulated human expert answering AG News articles together. The classifier is good everywhere, the expert is very good in some regions of the input space and worse than guessing in others, and the system has to work out who should answer what — first with the expert's answers in hand, then having to buy them one question at a time.

Task 2 · the simulated expert

An expert with a competence profile

Competence is attached to k-means regions of the document space rather than to the label. Tying it to the label would make task 4 trivial: the profile could be inferred from the classifier's own predictions without ever asking a question. Regions lean towards topics without being topics, so the profile has to be bought with queries. When the expert is wrong the wrong answer is drawn from a confusion profile rather than uniformly, and answers are fixed per article, so asking twice gives the same answer.

{# ---------------- task 3 ---------------- #}
Task 3 · learning to defer

Deciding who answers

With expert answers available for the whole training set, a rejector estimates P(expert correct | x) from the text alone, and the system defers when that beats the calibrated probability that the classifier is right. Calibration is not optional here: the raw maximum probability of a linear model is badly overconfident, and comparing it directly against the rejector makes the system defer far too rarely.

Gains caught is the share of articles that only the expert gets right which the system actually handed over. Damage is the share of all articles the system gave away that the classifier would have got right and the expert did not. Both matter more than team accuracy for judging the deferral decisions themselves, which is what the task asks for.

The learned rejector and the confidence rule land close on team accuracy, but they are not doing the same thing: the expert is right on {{ t3.learned.accuracy_deferred }} of what the rejector hands over against {{ t3.confidence_only.accuracy_deferred }} for the confidence rule, at {{ t3.learned.damage }} damage against {{ t3.confidence_only.damage }}. Confidence finds hard articles; the rejector finds articles this particular expert is good at, which is a different question.

The system recovers {{ t3.normalised_gain }} of the distance between the classifier alone and the oracle. The rejector's AUC for predicting whether the expert is right is {{ t3.rejector_auc }}.

Buying the profile one question at a time

The two figures disagree, and the disagreement is the finding. Random sampling builds the best competence model by AUC, because it trains on a representative sample of the input space. Deferral margin builds a worse model of the expert overall and a better team, because it spends its budget where the deferral decision is actually in the balance. Precision about the expert's competence in a region where the classifier is at 99% buys nothing: the system keeps those articles either way.

Classifier uncertainty, the textbook active learning baseline, is no better than random here. It selects articles that are hard to classify, which is a different question from where the expert helps. Expert uncertainty is worse than random: chasing points where the competence model is unsure gives it a badly skewed training sample, and its deferral rate collapses to {{ t4.summary.3.final_deferral }}.

Reproducing this

Rerunning the experiments

Everything on this page is read from project3/results/results.json, which is committed so the page works straight after a clone. To regenerate it:

python manage.py run_experiments

Takes about half a minute. Every step is seeded, so a rerun reproduces the committed numbers exactly. The figures on this page are redrawn from the JSON on each request, so no images are stored in the repository.
